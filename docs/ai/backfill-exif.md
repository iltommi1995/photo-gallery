# Playbook: backfill EXIF metadata

Used by the `backfill-exif` Claude Code skill and the Codex `/backfill-exif`
prompt. No dedicated sub-agent — this is a scoped, mostly-mechanical script
task, run via the general-purpose agent or directly.

## When to use this

- The EXIF extraction logic in `src/lib/exif/` changed (bug fix, new field
  supported) and previously-uploaded photos should be re-parsed.
- A batch of photos was inserted directly into storage/DB outside the normal
  upload flow (e.g. a migration from an old system) and never had EXIF
  extraction run.

## Steps

1. **Never touch manually-edited fields.** Any `Photo` row where an admin
   has hand-edited metadata (notably every `isAnalog: true` row — those have
   no EXIF to begin with) must be left alone. Only backfill fields that are
   currently `null` unless explicitly told to force-overwrite.

2. **Locate the source file.** Use `Photo.originalPath` (not the generated
   variants) — EXIF lives in the original upload, and variants generated by
   `src/lib/image/` deliberately strip it.

3. **Run extraction through the shared helper**, not a reimplementation —
   `src/lib/exif/extract.ts`'s exported function is the same one the upload
   route calls. Backfilling must produce identical results to a fresh upload.

4. **Batch, don't loop unbounded.** Process in small batches with a short
   delay/await between DB writes; this runs against the same Postgres
   instance the app serves from.

5. **Log what changed.** For each photo touched, note id + which fields were
   filled in, so the run is auditable. A dry-run mode (report without
   writing) should be the default; require an explicit flag to write.

6. **Verify.** Spot-check a handful of updated rows via `pnpm db:studio`,
   and confirm the public lightbox EXIF panel renders the newly-filled
   fields correctly for at least one photo.

7. **Changelog.** Only add a `CHANGELOG.md` entry if this playbook run
   accompanies a code change (e.g. fixing the extractor). A one-off data
   backfill with no code change doesn't need one.
